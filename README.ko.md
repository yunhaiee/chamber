# Chamber

법률사무소가 함께 쓰는 온디바이스 AI 하나. 각 모델은 해낼 수 있는 업무를 스스로 증명해 얻고, 비밀유지 대상 텍스트는 밖으로 나가지 않습니다.

[English](README.md)

AGI House *Personal Agent to Real-World Deployment* Build Day(2026년 11월)를 위해 만들었습니다.

## 문제

고객 파일을 클라우드에 올릴 수 없기 때문에 로펌은 온디바이스 AI를 원합니다. 하지만 전환한 뒤에도 일은 돌아가야 합니다. 하이브리드가 답이 될 수 있지만 어디에 선을 그어야 할지는 아무도 모릅니다. 작은 모델이 변호사의 업무를 실제로 얼마나 해낼 수 있는지는 로펌, 역할, 사람마다 다르기 때문입니다.

Chamber는 선을 긋지 않습니다. 사람별, 업무별, 모델별로 각 모델이 직접 그 선을 얻어냅니다.

## 작동 방식

| 단계 | 내용 |
|---|---|
| 판독 | Liquid의 d1-2B가 모든 요청을 기기에서 읽고, 비밀유지 대상인지, 사람이 필요한지, 어떤 종류의 업무인지 판단합니다. |
| 비밀유지 대상 | Liquid의 LFM3-1.7B가 기기에서 답합니다. 첨부된 고객 파일, 표시된 텍스트, 읽을 수 없는 텍스트는 d1의 점수와 상관없이 기기에 남습니다. |
| 새로운 공개 업무 | LFM3와 클라우드가 둘 다 답합니다. 변호사는 어느 쪽인지 모르는 두 답변 중에서 고릅니다. 좋은 결과가 3번 나오면 그 업무는 기기로 옮겨집니다. 3번이라는 기준은 데모를 짧게 하기 위해 정한 값입니다. |
| 클라우드 | 이름을 먼저 마스킹합니다. 키는 기기에 남고, 이름은 기기에서 복원합니다. |
| 법적 판단 | 사람에게 넘어갑니다. AI는 답하지 않습니다. |
| 정보 차단벽 | 변호사들은 모델 하나를 함께 쓰지만 서로의 사건은 볼 수 없습니다. 서버가 이를 강제합니다. |
| 감사 로그 | 해시 체인 로그가 무슨 일이 있었는지 대표 변호사에게 평이한 문장으로 알려줍니다. |

**같은 업무, 다른 결과.** 두 변호사가 "Public fee or limit" 업무를 실행했습니다. 한 가지 한도에 청구액을 대조하는 일은 기기로 옮겨졌습니다. 세 구간에 걸친 유언집행자 보수 계산은 LFM3가 틀렸기 때문에 클라우드에 남았습니다. 이 규칙은 아무도 작성하지 않았습니다.

## 측정 결과

Mac 노트북에서 시스템을 실행해 얻은 수치입니다.

- 시뮬레이션한 로펌의 하루에서 클라우드 호출 12회 절감.
- 두 쪽 모두 답한 요청 23건의 중앙값 기준 기기 1.0초, 클라우드 2.6초.
- d1은 테스트 요청 144건 중 144건에서 업무 종류를 맞혔고, 약 0.4초가 걸렸습니다.
- 비밀유지 대상 테스트 요청 중 0.30 기준에서 공개로 판정된 것은 없었습니다.
- 직접 작성한 공격 사례 136건은 한 번의 수정 후 비밀유지 대상 텍스트를 클라우드로 내보내지 못했습니다. `scripts/redteam_d1.py`로 실행할 수 있습니다.

## 실행 방법

Python 3.12, [Ollama](https://ollama.com), [llama.cpp](https://github.com/ggml-org/llama.cpp)가 필요합니다.

```bash
python3.12 -m venv .venv
.venv/bin/pip install fastapi uvicorn httpx anthropic pytest
ollama pull lfm3:1.7b
```

터미널 하나에서 판단 모델을 시작합니다.

```bash
llama serve -hf LiquidAI/d1-2B-GGUF:Q8_0 -b 8192 -ub 8192 --port 9931
```

다른 터미널에서 앱을 시작합니다.

```bash
export ANTHROPIC_API_KEY=...      # 파일에 저장하지 마세요
./scripts/clean_start.sh 8000
```

`clean_start.sh`는 시작하기 전에 데모 데이터베이스를 삭제합니다. 키가 없으면 클라우드 대신 로컬 `qwen3:8b`를 사용하며, `ollama pull qwen3:8b`가 필요합니다.

| 페이지 | 설명 |
|---|---|
| `http://localhost:8000/demo` | 채팅, Maya / Daniel 전환, 로펌 보드, 오른쪽 위 Reset이 있는 한 화면 |
| `http://localhost:8000/chat` | 변호사 한 명의 채팅 |
| `http://localhost:8000/` | 대표 변호사 대시보드 |

3분 데모 대본은 `DEMO.md`에 있습니다(영어). 테스트는 `.venv/bin/python -m pytest`로 실행합니다.

## 기술 스택

Python, FastAPI, SQLite, Ollama, llama.cpp, Liquid LFM3-1.7B, Liquid d1-2B, Claude API. 프런트엔드는 정적 HTML과 순수 JavaScript입니다.

## 범위

- 로펌, 사건, 문서는 모두 가상의 데이터입니다.
- Mac 노트북에서 실행했으며, 전용 AI 하드웨어에서는 아직 실행하지 않았습니다.
- 3번의 시도는 데모용 기준입니다. 실제 로펌이라면 훨씬 많이 필요합니다.
- 유출 테스트는 정확히 일치하는 고객 이름, 비밀값, 이메일, 문서의 8단어 연속 구절을 잡아냅니다. 바꿔 쓴 표현은 통과할 수 있습니다. d1도 잘못 판단할 수 있어 고정 규칙으로 보완합니다.
- 공격 사례는 직접 작성한 것이므로 보장이 아니라 테스트입니다.
- 파일 업로드와 실제 로그인은 구현하지 않았습니다. 파일은 미리 준비된 목록에서 고르며, `seed/users.json`의 PIN은 데모용 값입니다.
- 준비된 업무에 쓰인 캘리포니아 법 인용 일부는 공식 법전과 대조하지 않았습니다.
- 법률 자문이 아니며, 로펌의 직업윤리 의무를 대신하지 않습니다.
